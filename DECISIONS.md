# BoatScout implementation decisions

1. **Complete the product rather than pause after each phase.** The current user request authorizes building and improving the full project. BoatPrompt.md’s staged review instruction is treated as an earlier planning suggestion.
2. **Keep Next.js 15, export the frontend, split the API.** GitHub Pages cannot execute Next route handlers or background jobs. Next App Router exports the website; Fastify hosts the authenticated Node API. Both use the same typed filter engine. The backend can also serve the exported website.
3. **SQLite with Prisma is the default.** It gives a durable relational model and a one-command local setup. PostgreSQL/PostGIS and Redis would add services before there is a scale requirement. Haversine distance implements radius search. A PostgreSQL migration is future work, not an advertised alternate mode.
4. **Simple periodic Node worker.** A worker process performs collection followed by alert evaluation. Database leases prevent duplicate collector/alert runs across app/worker processes. This avoids Redis/BullMQ for a single user. The default 30-minute tick is configurable, minimum one minute. Leases are time-bounded; exceptionally long runs should be split into smaller source sets.
5. **Static sites get useful data modes.** Sample, published snapshot, and connected data are separate and visible. Browser storage is used only for standalone personal state and preferences. Connected state is in SQLite. Authentication sessions are held in sessionStorage and expire in 12 hours; passwords are not persisted by the frontend.
6. **Rich specifications in a catalog and validated JSON.** All requested filter attributes exist in lib/catalog.ts. Essential columns, engines, sellers and price history remain relational. Less common specs live in the canonical JSON payload, avoiding a huge nullable migration while preserving typed values and an extensible filter UI. The SearchArea model is available for reusable source-area records; per-search areas are currently stored inside SavedSearch.filters.
7. **Conservative normalization and deduplication.** Core metadata is extracted when available. Heuristic make/model/year results include confidence, and unknown specs remain unknown. Auto-grouping first restricts candidates to at most 100 other-source records with identical make/model/year, then requires HIN or a shared source image URL plus seller/core matches. This leaves same-source reposts and inconsistent identities unresolved, even where a broader identifier match could help. No perceptual-hash or fuzzy-title-only merges are claimed; see FUTURE_IMPROVEMENTS.md.
8. **Configured regional inventory with visible coverage limits.** Ten sources have dedicated live-tested collection: regional Craigslist, OnlyInboards, Bass Boat Central, and seven dealer inventories. Supported sites follow same-origin pagination with explicit page/detail caps. A repeated source ID is processed once per run so alternate page links cannot overwrite enriched details or inflate counts. Other marketplaces retain structured-data/selector fallbacks without a claim of live compatibility. Search-area filters are local and do not rewrite remote marketplace queries. [SOURCE_COVERAGE.md](SOURCE_COVERAGE.md) records included regions and gaps.
9. **Facebook is import-assisted.** This build accepts user-exported canonical records, not cookies or authenticated browser session harvesting. This protects reliability and avoids building an access-bypass dependency into the product. Other optional Playwright rendering is same-origin and checks robots first.
10. **Keep observed history on failures.** Empty/challenged pages are errors, not proof of removal. Unseen real listings become stale after 14 days; explicit source status can mark sold/removed. A source failure does not break other sources.
11. **Single-user auth, structurally separable users.** Workspace tables use user IDs. Today every session maps to the local user; multi-user auth needs a real identity provider/session store and ownership checks before exposing the app to several users.
12. **Lake Holiday screening with explicit provenance.** The user selected Lake Holiday, IL as home. The public 2024 association rulebook informs an editable strict-under-21-ft screen, with a warning about molded platforms, motor ratings, prohibited wakesurfing and use of wake-enhancing devices. Missing lengths fail this screen. Presets prioritize distance within 150 miles, offer fishing boats with reported 200+ hp and premium ski makes, and allow expansion to 250 miles. The main preset also screens out reported lengths below 18 ft. Separate broader views include unreported lengths or all nearby ads without a lake screen. A coverage panel explains the difference between the inventory pool and filtered matches. A model name or advertised nominal length does not establish registration eligibility.
13. **Observed market data only.** Charts use the current matches, deduplicated. They show asking prices and time tracked, not sales valuations or a complete historical market. Alerts compare saved-search matching state, baseline once, and enqueue durable changes.
14. **Licensed sample imagery.** Five local photographs represent broad boat categories. All seed listings and photos are labeled illustrative, source links point to example.com, and photo credits/licenses are bundled. No sample is presented as a verified live offering.
15. **Native HTML and accessible Radix composition.** Tailwind is available for utilities; a custom token-driven stylesheet supplies the nautical working-surface design. Native selects and checkboxes provide predictable keyboard behavior. Modal focus management uses Radix, following the shadcn composition pattern.
16. **GitHub deployment is prepared, not performed.** The user specified GitHub Pages and local execution. No Sites cloud project was created, and no unrelated hosting target was published. The supplied directory originally had no Git repository. It is now connected to the private PNelsonFTP/BoatMarket repository. A tested static export and deployment workflow are delivered; Pages jobs require the explicit BOATSCOUT_ENABLE_PAGES repository variable so a source push does not automatically publish the site.
17. **Patched dependencies without an unnecessary framework migration.** Retain the prompt’s Next.js 15 line, upgrade Fastify static serving and Nodemailer, and pin compatible patched PostCSS/deepmerge-ts transitive dependencies. The resulting runtime dependency audit is clean. Development and production build directories are separate so a static export can be built while the preview runs.

18. **Geographic precision is visible.** Public listing cities are geocoded once into a local cache; the worker does not run bulk geocoding. Distances are approximate straight-line miles. Ambiguous unresolved locations stay unknown. A boat explicitly stored off site is excluded from the default location screen until its actual location is known.
19. **Cached pages are observations, not new checks.** Cached collections use the saved page observation time. A recent local cache is read before network throttling; new outgoing page requests still require robots checks and crawl delays. Raw HTML lives once in the local cache, with source references and normalized payloads retained per record. The per-URL cache is overwritten on refetch and is not a complete historical evidence archive. Conflicting power and implausible length fields remain unknown with an explanation.
20. **Document the delivered state and inventory scope.** README, OPERATIONS, HANDOFF, SOURCE_COVERAGE, LIVE_DATA, VALIDATION, CHANGELOG, and FUTURE_IMPROVEMENTS separate implemented behavior, observed results, and proposed work. SBOM.md explains reproducible CycloneDX inventories, the complete lock-entry inventory, dependency audit dates, and optional bundled dependency unknowns. No new daily/weekly automation or unresolved application fix is implied by this documentation pass.
