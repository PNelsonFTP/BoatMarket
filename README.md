# BoatScout

**Live website:** [pnelsonftp.github.io/BoatMarket](https://pnelsonftp.github.io/BoatMarket/) — the reviewed September 12 inventory snapshot. Collection and private workspace storage run locally.

A boat-search workspace with a GitHub Pages website and an authenticated local backend. Search, save, compare, map, track prices, and monitor boat listings across configured sources.

**Start here:** the review website is served at **http://127.0.0.1:4310** by `npm start` after `npm run build`. The existing desktop checkout is installed and initialized; a fresh clone needs the setup steps below. The website opens a dated collected snapshot with Lake Holiday, IL as home. See [LIVE_DATA.md](LIVE_DATA.md) for the latest scan, coverage and results. To use the local database, open **Settings → Your backend**, keep `http://127.0.0.1:4310`, and enter `BOATSCOUT_PASSWORD` from your local `.env` file. That password is generated by setup and is never bundled into the website. For development with automatic collection, use `npm run dev` and follow the printed website address.

**September 8 P1/P2 update:** all implementation areas are mapped in [P1_P2_IMPLEMENTATION.md](P1_P2_IMPLEMENTATION.md). The current official publicly linked Lake Holiday rulebook permits hulled boats **up to 21.0 ft inclusive**, including molded platforms; reviewed profile updates preserve customized searches. Seller/association confirmation remains separate. Source access gaps and owner-controlled providers/services/publication remain explicit.

If another application uses port 3000, preserve it. Run `npm run build` followed by `npm start` and open **http://127.0.0.1:4310** for the website and API together; run `npm run worker` separately when collection is wanted. Browser tests use isolated port 3002.

## First-time installation on another machine

Use Node.js **22 LTS** (22.12 or later) and npm. No database service, Redis, or Docker is required for local development.

```bash
git clone https://github.com/PNelsonFTP/BoatMarket.git
cd BoatMarket
npm ci
npm run setup
npm run dev
```

`setup` creates `.env` with a random password, creates the local data directory, generates the Prisma client, and applies committed migrations. It preserves an existing `.env` and database. `dev` runs:

- Website: http://127.0.0.1:3000
- API: http://127.0.0.1:4310
- Background collector and alert worker, every 30 minutes by default

Stop all three with Ctrl+C. Your data stays in `data/boatscout.db`. The backend initially starts empty. To put the same 52 fictional examples in the backend, run `npm run db:seed`. This checkout retains its original seed data separately, but the API and publication export show real records. Every seed record has `isSample: true`; sample records are excluded from alert evaluation and the command-line publication snapshot.

On macOS, double-click **Start-BoatScout.command**. On Windows, run **Start-BoatScout.bat**. Cursor/VS Code also has tasks under **Terminal → Run Task → BoatScout: start website, API & worker**. No Cursor-specific API is needed.

## What works

- Keyword search; an expandable, searchable filter catalog for every attribute listed in BoatPrompt.md.
- Numeric ranges, multiple categorical values, equipment include/exclude/any, and per-field or global unknown handling.
- Multiple radius/state/map-box areas, combined with OR. All other active criteria are combined with AND.
- Boat vs. seller location, reference distances, lake rules, allowed propulsion, excluded categories, and towing limits.
- Grid/list/map views; clustered map pins; ordering by price, price/foot, first seen, distance, hours, year, and time on market.
- Shortlist, private notes, data flags, photo galleries, source links, engine records, price history, similar boats, and comparison of up to six boats.
- Saved searches; in-app alerts; email and webhook delivery; hourly/daily/weekly cadence; optional digest.
- Market charts for the current filtered dataset.
- Source health with a dated coverage-gap ledger, page/detail caps, cache/fetch metrics, and explicit refresh outcomes.
- Reversible duplicate review, permanent vessel identities/timelines, HIN conflict protection, original-image evidence and active/nearby/changed-review filters.
- Validated, chunked full-dataset imports with progress and failure manifests; previewed workspace merge/restore.
- City-center and reversible actual-boat location review; per-field source history; configured driving-time estimates and optional four-hour filter; shared geocoder throttling/backoff.
- Downloadable comparison packets with printable seller and inspection checklists.
- Verified SQLite/configuration/snapshot backups, safe restore into a new directory, reviewed retention and free-space checks.
- Rotating detail checkpoints, source-quality gates, immutable capture history, redacted fixtures and reviewed parser repair.
- Supervised worker templates, cooperative cancellation/recovery, configurable alert events and per-channel retry diagnostics.
- Atomic snapshot generations, privacy/quality/source/SBOM release review and explicit manual GitHub Pages publication.
- Light/dark mode, mobile layouts, native keyboard controls, and Cmd/Ctrl+K search focus.
- Authenticated, validated API with rate limits and optimistic concurrency for workspace updates.

## Three data modes

| Mode | Listings | Favorites, notes and searches | Scheduled collection/alerts |
|---|---|---|---|
| Sample | 52 fictional listings generated in the browser | This browser’s sample workspace | No |
| Snapshot | Published `snapshot.json`, or a JSON file imported for the current session | This browser’s snapshot workspace | No |
| Connected | Local API and SQLite database | Persisted in the backend | Yes, while the worker runs |

Connected workspaces also keep an isolated browser backup; the backend remains authoritative and that cache is never silently restored over it. Connecting opens a separate backend workspace. It does not silently copy fictional listings or sample notes into your real database. Browser storage is separated by deployment path, data mode, and backend URL. Earlier unscoped browser workspaces can be deliberately restored through Settings; they are not silently copied. The top banner always identifies the current mode. Sample photographs illustrate boat categories and are **not photos of the named model or an actual offering**. See [PHOTO_CREDITS.md](PHOTO_CREDITS.md).

## GitHub Pages

GitHub Pages serves static HTML, JavaScript, and assets; it does not run the database, API, or background jobs. BoatScout exports the website to `out/` with relative project support and `.nojekyll`. See [GitHub’s Pages overview](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) and [Next.js static exports](https://nextjs.org/docs/app/guides/static-exports).

1. The public repository is [PNelsonFTP/BoatMarket](https://github.com/PNelsonFTP/BoatMarket), with `main` as the primary branch. Do not add `.env`, `data/`, or `logs/`; they are ignored.
2. GitHub Pages is configured for **GitHub Actions**, with HTTPS enforced, at [pnelsonftp.github.io/BoatMarket](https://pnelsonftp.github.io/BoatMarket/). The reviewed 1,667-ad snapshot is live; deployment and desktop/mobile verification passed on September 12.
3. Set the repository Actions variable **`BOATSCOUT_ENABLE_PAGES` to `true`**. Prepare and approve an exact-hash release with `npm run release` (see OPERATIONS.md), commit its matching source/snapshot/SBOM/manifest, then manually dispatch `.github/workflows/pages.yml` with that review hash. Main pushes do not publish; the Pages workflow refuses unreviewed or mismatched artifacts.
4. The independent validation workflow runs on pushes to `main` and pull requests regardless of Pages settings. The Pages workflow obtains the repository base path from `configure-pages`, so `/BoatMarket/` works without edits. Configure custom domains in Pages settings if needed.

The workflow uses GitHub’s [custom Pages workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) actions. The September 8 setup attempt returned HTTP 422 while the repository was private. On September 10 the owner authorized public visibility, the repository became public, and Pages configuration succeeded. The reviewed local website remains available at port 4310. Future public updates require local collection/export, release review, a commit of the matching artifacts and a manual Pages deployment; publishing the repository does not start a hosted backend or collector.

### Option A: Publish a snapshot — simplest

Collect/import listings locally, then:

```bash
npm run refresh
npm run build
```

A successful full refresh backs up the database, collects, validates the outcome, writes an immutable snapshot generation, and atomically activates its pointer in `public/data-mode.json`. Partial or failed collection preserves the previous snapshot. To export an already-reviewed database without collection, use `npm run export:snapshot`. Review the exported listing data through the release workflow before committing the matching generation, pointer, SBOM and release manifest. Raw payloads, sample listings, notes, favorites, alert destinations, and credentials are excluded. The public site works while your computer is off. Update the snapshot whenever you want fresh listings. Restore `{"snapshot":false}` in `public/data-mode.json` to show the built-in samples again.

A snapshot exported by the Settings button includes all currently displayed source records, including explicitly labeled samples. Importing a JSON file in Settings changes the current session; exporting/publishing it makes it persistent across reloads.

### Option B: Connect Pages to your backend

Run the backend on a home server/VM or your machine, make it reachable over HTTPS using your preferred reverse proxy or secure tunnel, and add the exact Pages origin (e.g. `https://yourname.github.io`, without a repository path) to `ALLOWED_ORIGINS`. Enter the HTTPS backend URL and password in the site’s Settings.

Optionally set the repository Actions variable `BOATSCOUT_API_URL` to prefill the connection address. **Never put a password in a `NEXT_PUBLIC_*` variable or repository variable used by the frontend build.**

A public HTTPS page connecting to `http://127.0.0.1` can be blocked by browser mixed-content or local-network protections. If that occurs, use the local website, an HTTPS backend, or snapshot mode. A backend on your machine is available only while it is running and your machine is reachable.

### Test a repository-path export locally

```bash
NEXT_PUBLIC_BASE_PATH=/BoatMarket npm run build
```

Serve `out/` under `/BoatMarket/`, not at the server root. For the normal local build omit `NEXT_PUBLIC_BASE_PATH`.

## Local production and Docker

To serve both the built website and API from one local address:

```bash
npm run build
npm start
```

Open http://127.0.0.1:4310 and connect to that same address in Settings. Run `npm run worker` in another terminal for scheduled jobs, or `npm run collect` for one cycle.

For Docker, first run `npm run setup` to create `.env`, then:

```bash
docker compose up --build -d
```

Open http://127.0.0.1:4310. Compose runs the static website/API and worker as separate services sharing named data, configuration and log volumes. The worker waits for app health. A new configuration volume is seeded from the image; later image rebuilds preserve that volume's configuration. Review and apply configuration changes through the connected Settings workflow. The runtime runs as user 1000; older root-owned volumes may need a deliberate ownership migration after backup. The default port binding is loopback-only. Configure a reverse proxy deliberately if remote access is needed.

```bash
docker compose logs -f app worker
docker compose down
```

`down` keeps the named volumes. Do not add `-v` unless you intend to delete their data. The default `runtime` target supports static HTML/JSON-LD collection. Set `BOATSCOUT_DOCKER_TARGET=rendered` in `.env` and rebuild to use the included Chromium target for `render: true` sources. See [SBOM.md](SBOM.md) for the exact tested images and their OS/native/browser inventories.

Container collection updates the shared database, which is visible in connected mode. Container snapshot export and **Refresh data & snapshot** are currently unsupported: the image serves its built `out/` files and has no shared writable `public/` publication directory. Keep `WORKER_AUTO_EXPORT=false` (the default) for Compose; use **Run enabled sources** and reload connected data. Build reviewed snapshots in a host checkout and rebuild the image when its static website needs new data. Built website files are copied with ownership readable by the non-root runtime, including private-mode snapshot pointers.

## Adding real listings and sources

### Manual listing

Open **Settings → Your data → Add a boat**. Supply the original listing URL, title, and known specifications. Leave missing values blank. Connected mode persists the record to the database; standalone mode creates a session snapshot.

### JSON import

Use **Settings → Import listings** with an object containing a `listings` array. Download the example from the site or inspect `public/import-example.json`. The canonical Zod schema is in `lib/types.ts`; filter attributes not represented by dedicated properties belong in `specs`. Unknown values are `null`, not zero or fabricated guesses. Prices are USD. Set `isSample: false` only for actual listings. The example is intentionally marked as a sample. The import preview validates the entire file and sends connected imports in chunks of at most 1,000 records and 12 MiB. It stops at the first failure and offers a manifest of accepted, failed, uncertain, and unattempted IDs for safe retry. **Restore workspace** previews notes, favorites, searches, rules and references; merge preserves current edits by default. Explicit replacement first downloads a backup and still checks the backend revision.

### Configure an adapter

Open **Settings → Sources & collection → Edit configuration**. Enter one or more search/inventory URLs, choose the right adapter, and enable it. Search the marketplace yourself to create a URL for each desired area. The collector fetches these configured inventory pages; changing a dashboard filter does not automatically rewrite external marketplace queries or crawl every page on a marketplace.

All configured sources live in `config/sources.json`. Save configuration, run enabled sources, and refresh status to review results. This checkout enables twelve sources, including regional classifieds and nine dealer inventories. See [SOURCE_COVERAGE.md](SOURCE_COVERAGE.md) for the source list, geographic scope and remaining gaps. Restricted prospects remain disabled with their URLs and access history retained. An adapter with a robots denial or access challenge stops; it does not attempt to bypass the restriction. Requests are throttled with jitter and cached for 24 hours by default, and failed sources do not stop others. Configure `cacheMaxAgeHours` per source (1–720 hours), `COLLECTION_CACHE_HOURS` globally, or `--cache-hours=N` for one CLI run. Inventory caps and failed requested details report partial coverage; planned rotating detail deferrals are reported separately.

| Adapter | Implementation and current limits |
|---|---|
| Boat Trader | Product/Vehicle/Boat JSON-LD including nested ItemList. Fixture-tested. Live pages may restrict access or omit public metadata; use selectors or import. |
| YachtWorld | Same structured-data parser, isolated source configuration. No proprietary API credentials included. |
| Craigslist | Structured data and static/current result-card selectors. Configure a separate search URL for each region. Public static results are joined to structured metadata by ad identity; preferred makes receive detail enrichment. This checkout covers 17 regional boards. No complete-market census is claimed. |
| Facebook Marketplace | Manual user-exported canonical JSON only. Cookie/session automation is deliberately not included; there is no login bypass or credential import. |
| Boats.com, iboats, eBay Motors | Structured-data adapters, configurable selector fallback. No guarantee of current live markup or complete pagination. Non-USD structured offers are skipped. |
| Dealer | Dedicated live-tested Bedford Sales, OnlyInboards, Miller’s, Dealer Spike, Gordy’s, Bass Boat Central and Starved Rock parsers, plus generic selectors. Supported sources follow pagination with `autoPaginate` and `maxInventoryPages`. Detail collection uses `followDetails`, `maxDetailPages`, `detailMaxLength` and optional `detailMakes`. |
| Manufacturer CPO | Structured-data/selector adapter for a manufacturer’s chosen inventory URL; no claim that any particular brand currently offers a public CPO feed. |

Example dealer configuration:

```json
{
  "id": "local-dealer",
  "name": "My Local Dealer",
  "adapter": "dealer",
  "enabled": true,
  "urls": ["https://dealer.example.com/used-boats"],
  "area": "Local inventory",
  "selectors": {
    "item": ".inventory-item",
    "title": ".title",
    "link": "a",
    "price": ".price",
    "image": "img",
    "location": ".location"
  }
}
```

Replace the example domain and selectors with those on the actual public page. Public HTTP(S) endpoints on standard ports are supported. Private, loopback and reserved IP targets are blocked. Redirects across origins require configuring the final URL explicitly.

To add code for a source, implement the `Adapter` interface in `server/adapters/types.ts`, register it in `server/adapters/index.ts`, add its config type and fixture, and test normalization in `tests/adapters.test.ts`. `normalizeListing` preserves provenance and annotates heuristic fields. The collector stores original HTML once in its local cache and retains normalized payloads and evidence references in the database. It never marks all unseen boats removed after a partial/failed search; real active records become `stale` after 14 days without observation. Explicit sold/removed records keep their price histories and notes.

`render: true` optionally uses Playwright after the robots check, with same-origin requests only and no browser-session credentials. Install Chromium locally with `npx playwright install chromium`. This is a restricted rendering aid; sites dependent on third-party scripts may still require manual import.

## Refresh and schedules

Run `npm run refresh` for backup → collect → validate → atomic snapshot export. Add `-- --geocode` to resolve newly discovered cities using an enabled provider and bounded lookups. Source errors, inventory caps and failed required detail work produce exit **2** and preserve the previous snapshot; planned rotating detail deferrals are reported separately. Exit **0** means success, **1** failure, **3** busy, and **130** cancellation. After inspecting the report, `--allow-partial` can deliberately export a partial dataset with that status recorded; it still returns 2.

In connected mode, **Settings → Source health & refresh → Refresh data & snapshot** runs the same pipeline and shows its outcome. **Run enabled sources** collects only; **Refresh data** reloads the database only. The public health endpoint checks database connectivity and reports worker heartbeat status. Authenticated source health includes page/detail counts, cache observations and the dated missing-source ledger. Reports persist in `data/refresh-runs/`.

The worker runs every 30 minutes after each completed cycle while the process/computer is running. Set `WORKER_INTERVAL_MINUTES=1440` for daily intervals or `10080` for weekly, and `WORKER_AUTO_EXPORT=true` to run the complete safe snapshot pipeline on daemon cycles. `WORKER_AUTO_GEOCODE=true` additionally enables bounded city lookups. No OS schedule or Codex automation was installed; these are interval settings, not fixed wall-clock appointments. Builds, commits and publication remain separate. Collection interval, cache freshness and saved-search alert cadence are different settings. See [OPERATIONS.md](OPERATIONS.md).

## Alerts

Save a search while connected, open **Saved searches**, and choose a cadence, event types and delivery channels. The worker evaluates searches after collection, so delivery can be later than the selected cadence. The first check establishes a baseline; it does not send every existing boat. Selected events include new matches, price drops/changes, status changes and boats no longer matching. A sold boat leaving an active-only search can still produce the selected status event.

For email, set `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `ALERT_EMAIL`, and any required `SMTP_USER` / `SMTP_PASSWORD` in `.env`. For HTTPS push/webhooks, set `ALERT_WEBHOOK_URL`. The generic webhook posts JSON with `id`, `title`, `message` and `listingIds`. ntfy/Pushover integrations may need an endpoint that translates this payload to their expected format; direct service-specific integrations are not assumed. Notifications may contain listing descriptions/links: only configure destinations you control.

The UI supports a combined digest or one alert per matching change. Failed deliveries remain visible in Settings; the worker checks due retries every minute between collection cycles. `ALERT_MAX_ATTEMPTS` defaults to five; backoff and per-channel outcomes prevent immediate repeated sends or resending a confirmed successful channel. Delivery is at-least-once; cooperating recipients can deduplicate by alert `id` / email Message-ID. Changing SMTP/webhook settings requires restarting the processes. No emails or webhooks are sent unless you configure a destination and enable that channel.

## Rules, distances, and missing values

Open **Settings → Lake & towing rules** to add/edit limits. Apply the named rule from the Discover filter rail. A saved search captures the rule as it was saved; edit/re-save the search to adopt later rule changes. The editable Lake Holiday screening preset uses an inclusive 21.0-ft limit from the official publicly linked December 2, 2025 association rulebook, reviewed September 8, 2026. Settings offers a reviewed update for old factory profiles while preserving customized searches. It is a screening aid, not registration approval. Wakesurfing and use of wake-enhancing devices are prohibited by that publication; current rules and platform measurement require association confirmation. See [LIVE_DATA.md](LIVE_DATA.md).

Length and beam/draft are decimal feet (18 ft 6 in = 18.5); shaft length is inches; weights and thrust are pounds. Radius distances are great-circle miles. Configured road routes show driving estimates separately. Reference places can be added in Settings. Place lookup uses cached queries and shared provider throttling/backoff. Public Nominatim requires explicit `GEOCODER_PUBLIC_POLICY_ACCEPTED=true`; recurring batches are limited to four requests per minute under its [usage policy](https://operations.osmfoundation.org/policies/nominatim/). The site does not send keystrokes for autocomplete. Batch enrichment requires matching city/state evidence, considers ZIP and suburbs, and queues ambiguous results. **Settings → Location review** corrects approximate city centers with local evidence; exact source coordinates remain unchanged and offsite boats are not assigned the seller’s location. Actual boat-location corrections are a separate reversible private workflow.

Unknown values pass an active filter unless you check its **Exclude unknown**, enable the global unknown exclusion, or require known values in a rule. Boolean equipment filters have Any, Include/yes, and Exclude/no. Known-photo counts and `hasPrice` are computed from the record. Price drops compare the latest asking price to the observed price at the start of the chosen window (or first observation inside it).

## Operational limits

This is a single-user, local-scale app. The browser and API evaluate the full listing dataset in memory for consistent rich filtering. It is suitable for a personal catalog, not an unbounded nationwide multi-user warehouse. For that workload, migrate Prisma to PostgreSQL, move filter predicates/pagination to database queries, and add a persistent job queue. The included SQLite database is not a drop-in PostgreSQL migration.

Automatic grouping requires matching structurally valid modern HINs, independent of model spelling and source. Conflicting valid HINs and reviewed “different boat” decisions block even transitive merges. Same-source reposts and matching specifications/photos become review suggestions. Decisions are reversible; original ads, source links, price histories, notes and favorites remain intact. Run `npm run duplicates:review -- --dry-run` before an explicit `--apply` reindex.

Six evidence-backed decisions consolidate seven original ads into two groups and keep two conflicting-HIN stock boats separate. Every real ad has a permanent vessel identity; ungrouped identities still need review and are not proven distinct vessels. Candidate counts change with the data and queue filters. Market charts distinguish matching ads from grouped research records. Optional local perceptual image audits and configured road-time estimates are implemented; exhaustive marketplace access, ongoing identity review and multi-user hosting remain open. See [FUTURE_IMPROVEMENTS.md](FUTURE_IMPROVEMENTS.md).

Use `npm run backup` for a consistent SQLite copy, integrity check, configuration/evidence files and a hash manifest under ignored `data/backups/`. Keep `.env` separately in secure storage; backups intentionally exclude secrets. See the tested recovery procedure in [OPERATIONS.md](OPERATIONS.md). Docker data lives in its named volume, not the host `data/` folder. Treat a published snapshot as public. Sessions expire after 12 hours and are invalidated when the API restarts. The static website has no analytics/tracking code; loading external source photos, map tiles or geocoding still contacts their providers.

## P1/P2 operation and release workflow

See [OPERATIONS.md](OPERATIONS.md) for exact commands and configuration. `npm run service` generates a project-specific background-service template; install is explicit. `npm run retention` and `npm run restore -- --help` begin with review. `npm run source:tools -- --help` provides capture, parse preview and exact-hash reparse. `npm run release -- prepare` creates a private publication review; approved source/snapshot/SBOM/build correspondence is required by the manual Pages workflow. Main pushes validate code and do not automatically publish. The public GitHub repository retains first-party `UNLICENSED` metadata and npm `private: true`; visibility did not change licensing or enable npm publication. No external provider or delivery destination is enabled implicitly.
