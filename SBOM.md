This package records the dependencies actually locked for BoatScout 1.0.0. It contains two CycloneDX 1.5 JSON SBOMs generated by npm, the complete available lockfile inventory, generation evidence, and fresh read-only vulnerability reports. It does not change or install dependencies.

Generated **September 7, 2026 at 9:40 PM America/Chicago** (`2026-09-08T02:40:29.540Z`) with Node `v26.7.0` and npm `11.19.0`. The project supports Node `>=22.12.0`; GitHub Actions and the Dockerfile use Node 22. These tools' recorded versions describe the generation environment, not a pin for all deployments.

## License metadata and external materials

There is currently **no first-party `LICENSE` file or `license` field** declaring a license for BoatScout's own code. `private: true` prevents normal npm publication; it does not choose a source-code license. The owner should make that choice deliberately before distributing the project.

Third-party declared licenses are not all MIT. The lock includes Apache-2.0, BSD variants, ISC, LGPL-3.0-or-later and compound expressions, MPL-2.0, CC-BY-4.0, BlueOak-1.0.0, MIT-0, and 0BSD. ## Regenerate and validate

Run from the project root after a deliberate dependency update:

```sh
npm run sbom
```

To also request new read-only registry audit reports:

```sh
npm run sbom:audit
```

The ordinary run reads local manifests/lock metadata and generates the SBOM files; it does not refresh audit reports. `--audit` creates timestamped audit JSON files and updates `audit-provenance.json`. Existing dated audit reports remain as historical evidence. Keep the matching provenance with any archived release. Generation timestamps and npm's serial UUIDs change between runs, so semantic dependency content is reproducible with the same lockfile and npm version, not byte-for-byte output. Review this human-readable document when versions or counts change.

The script checks JSON parsing, the expected CycloneDX version, uniqueness and completeness of component/graph references, exact name/version correspondence to lock entries, all emitted integrity hashes against the lock, preservation of every lock entry in the supplemental inventory, and that the lockfile did not change during generation. It records those checks in `provenance.json`. **It does not perform full CycloneDX JSON Schema validation**, package signature validation, independent tarball hashing, or semantic version-range verification of each supplemental edge.

## Deployment limits and follow-up work

- The production SBOM describes npm's production dependency graph, not precisely which code the browser bundles or backend executes.
- The Dockerfile copies the complete build `node_modules` tree into the runtime image. A production-only SBOM therefore does not completely describe that image. Generate an image SBOM for an immutable built image digest before treating a container inventory as complete.
- Node, Debian/system packages, browser downloads used by Playwright, downloaded/generated Prisma engines, and the hosting platform are outside these npm SBOMs.
- GitHub Actions versions and the Docker base image are referenced by mutable version tags. Pin reviewed commit/image digests and track them in release provenance if reproducible releases are required.
- Add full schema validation, release-time SBOM generation, dated audit review, and a complete platform/bundled-content inventory to the release process. A zero-advisory result should not suppress review of collector, authentication, privacy, and deployment behavior.
